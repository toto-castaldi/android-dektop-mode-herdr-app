# Configuration and local runtime

- **Prerequisiti di sviluppo:** JDK 21, Android SDK con `ANDROID_HOME` impostato (o `sdk.dir` in `local.properties`, fuori dal repository) e le licenze accettate, `tar` con supporto xz e accesso di rete al primo build; Gradle solo tramite il wrapper del repository, che scarica la distribuzione con checksum verificato. Platform, build-tools, NDK e CMake mancanti vengono installati dall'Android Gradle Plugin al primo build; Zig non va installato (vedi *Build nativa del terminale*). Host di build supportati: Linux e macOS, x86_64 e aarch64. `adb` e il Pixel 11 Pro servono per test strumentali ed end-to-end.
- **Toolchain bloccata:** versione di Gradle e checksum in `gradle/wrapper/gradle-wrapper.properties`; JDK, compileSdk, minSdk, targetSdk, Android Gradle Plugin, Kotlin, ktlint, detekt, NDK, CMake, Zig, libghostty-vt, il font del terminale, i checksum SHA-256 dei loro archivi e tutte le dipendenze in `gradle/libs.versions.toml`. I moduli usano il Kotlin integrato nell'Android Gradle Plugin e la toolchain Java del version catalog. Si aggiorna una versione solo nel version catalog o nel wrapper.
- **API level:** minSdk e targetSdk sono l'API level del Pixel 11 Pro di riferimento (`adb shell getprop ro.build.version.sdk`); compileSdk è lo stesso API level con la minor release più recente richiesta da AndroidX.
- **Struttura Gradle:** progetto radice `herdr-desktop-android` con tre moduli, uno per modulo logico (`docs/design/modules.md`): `:app` (applicazione Android), `:core-client` e `:terminal` (librerie Android). Il package base è `io.github.totocastaldi.herdrdesktop`; ogni libreria ha il proprio sottopackage (`.coreclient`, `.terminal`). I sorgenti stanno in `src/main/kotlin`, i test JVM in `src/test/kotlin`, quelli strumentali in `src/androidTest/kotlin`. La logica di build condivisa (task di download verificato, estrazione, build Zig, asset da uno zip, copia del `NOTICE`) è in `buildSrc/`.
- **Controlli statici:** ktlint (stile `android_studio`, regole in `.editorconfig`) e detekt (configurazione predefinita più `config/detekt/detekt.yml`) sono applicati dal build radice a ogni modulo.
- **Build nativa del terminale:** `:terminal` collega staticamente libghostty-vt (ADR-001) nella libreria JNI `libherdrterminal.so`, solo per `arm64-v8a`. I task `:terminal:download*` scaricano l'archivio di Zig per l'host da `ziglang.org` e i tarball sorgenti e dipendenze di libghostty-vt da `release.files.ghostty.org` in `~/.gradle/caches/herdr-desktop/downloads/`, condivisa tra i cloni, e li verificano con i checksum del version catalog: un checksum diverso fa fallire la build e il file non viene usato. `:terminal:buildLibGhosttyVt` compila senza rete (`zig build --system` con le dipendenze del tarball, cache Zig vuota) per `aarch64-linux-android` all'API level più alto del sysroot dell'NDK (nel version catalog, ≤ minSdk), `ReleaseFast`, CPU `baseline`, senza simboli; CMake (`terminal/src/main/cpp/`) compila il codice JNI contro la libreria statica, con pagine da 16 KB. La prima build nativa richiede alcuni minuti; le successive la riusano finché versioni e sorgenti non cambiano. L'avviso dell'Android Gradle Plugin sull'API level oltre quello dell'NDK è atteso. I test JVM non caricano la libreria nativa; il binding si prova con i test strumentali di `:terminal`.
- **Font del terminale:** `:terminal:downloadTerminalFont` scarica l'archivio della release di JetBrains Mono da GitHub nella stessa cache e lo verifica con il checksum del version catalog; `:terminal:terminalFontAssets` ne estrae i quattro TTF (regolare, grassetto, corsivo, grassetto corsivo) e `OFL.txt` negli asset della libreria (`terminal-font/`), che finiscono nell'APK. Aggiornarlo: nuova versione e checksum nel version catalog e testo della licenza in `NOTICE`.
- **Aggiornare libghostty-vt o Zig:** nuova versione e nuovi checksum nel version catalog, letti da `SHA256SUMS` della release di libghostty-vt e da `https://ziglang.org/download/index.json`; la versione di Zig è quella di `minimum_zig_version` in `build.zig.zon` di libghostty-vt; poi aggiornare `NOTICE` dalle voci `"use": "linked"` di `deps/libghostty-vt-third-party.json`.
- **Desktop Mode:** l'activity principale è ridimensionabile e gestisce da sé i cambi di dimensione e densità della finestra, con dimensione iniziale e minima dichiarate nel manifest.
- **Dipendenze di runtime e licenze:** ConnectBot sshlib (Apache-2.0) solo in `:core-client`, con le sue dipendenze Tink, Ktor, kotlincrypto, kyber e keccak (Apache-2.0), protobuf (BSD-3-Clause), kstatemachine (BSL-1.0), Kaitai Struct runtime e SLF4J API (MIT), jbcrypt (ISC); kotlinx-coroutines e kotlinx-serialization (Apache-2.0); in `:terminal` libghostty-vt (MIT) con il codice che collega staticamente: simdutf (Apache-2.0/MIT), Highway (Apache-2.0/BSD-3-Clause), uucode (MIT e Unicode-3.0), Wuffs (Apache-2.0/MIT), translate-c e la libreria standard di Zig (MIT). Il font del terminale JetBrains Mono è sotto SIL Open Font License 1.1, compatibile con la distribuzione nell'app. Le licenze del codice nativo e del font sono in `NOTICE`, nel repository e nell'APK come `assets/NOTICE`. Tutte compatibili con Apache-2.0; una nuova dipendenza si verifica prima di aggiungerla (`./gradlew :app:dependencies --configuration debugRuntimeClasspath`).
- **Configurazione dell'app:** nessuna variabile d'ambiente né file di configurazione con segreti; macchine e chiavi si configurano dall'app.
- **Comandi:** quelli del quality gate e dei test strumentali in `AGENTS.md` §6.
